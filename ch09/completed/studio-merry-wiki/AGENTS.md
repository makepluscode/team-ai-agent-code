# 스튜디오 메리 팀 위키 규칙

이 파일은 팀 위키의 규칙 파일입니다. 헤르메스는 위키 폴더에서 실행될 때 이 파일을 읽고, 위키 페이지를 이 규칙대로 정리합니다. 사람이 읽고 고칠 수 있게 짧게 유지합니다.

## 폴더

| 폴더 | 넣는 것 | 고치는 사람 |
|---|---|---|
| raw/ | 원본. 메모·리포트 요약·작업 결과·회의 기록 | 아무도 고치지 않음. 넣기만 함 |
| wiki/ | 위키 페이지, index.md(목록), log.md(기록) | 위키 정리 담당 에이전트만 |
| guides/ | SOUL.md(공통 말투), brands/(고객별 지침) | 지침 담당자 |
| skills/ | 팀 스킬 | 스킬 담당자 |

## 원본(raw)

- 파일 이름은 `YYYYMMDD_고객ID_종류.md`로 씁니다. 예: `20261005_BB_brief.md`. 캠페인이 정해져 있으면 `YYYYMMDD_고객ID_캠페인ID_종류.md`.
- 고객 ID는 BB(봉봉소프트), DP(데얼즈파이), LB(런던뷰티랩)입니다. 고객이 없으면 `TEAM`을 씁니다.
- 원본은 넣은 뒤 고치지 않습니다. 내용이 바뀌면 새 날짜의 원본을 넣습니다.

## 위키 페이지(wiki)

- 페이지 종류와 위치: 고객 `wiki/clients/<고객ID>.md`, 캠페인 `wiki/campaigns/<캠페인ID>.md`, 리서치 `wiki/research/<주제>.md`, 결정 `wiki/decisions/<날짜>_<주제>.md`, 판단 기준 `wiki/criteria/<주제>.md`.
- 페이지 맨 위에 머리말을 둡니다.

  ```yaml
  ---
  type: client            # client | campaign | research | decision
  id: BB
  updated: 2026-10-05
  sources:
    - raw/20261005_BB_brief.md
  ---
  ```

- 사실 문장마다 끝에 출처를 붙입니다. 형식은 `(출처: raw/파일명)`입니다.
- 원본에 없는 사실은 쓰지 않습니다. 정해지지 않은 조건은 `확인 필요`로 남깁니다.
- 다른 고객의 사실을 섞지 않습니다. 한 페이지는 한 고객이나 한 캠페인만 다룹니다.
- 기존 페이지와 다른 내용이 들어오면 덮어쓰지 않습니다. `서로 다름` 항목에 두 내용과 출처를 함께 적고 사람이 정하게 합니다.
- 기존 페이지를 지우고 새로 쓰지 않습니다. 필요한 부분만 고칩니다.

- 원본이 이전 조건을 바꾼다고 밝히고 확인한 사람과 날짜가 있으면 현재 조건을 고칩니다.
  이전 조건은 '변경 이력'에 날짜와 출처를 붙여 남깁니다.
- 바꾼다는 근거 없이 값만 다르면 '서로 다름'에 두고 사람이 정하게 합니다.
- 판단 기준 페이지는 `wiki/criteria/<주제>.md`에 둡니다. 기준마다 종류(직군 판정·확인 규칙), 상태(후보·승인·적용·철회), 근거 사례의 출처를 적습니다.

## 목록과 기록

- `wiki/index.md`: 페이지마다 한 줄. `- [제목](경로) — 한 줄 요약 (갱신 YYYY-MM-DD)`
- `wiki/log.md`: 정리할 때마다 맨 아래에 한 줄 추가. `- YYYY-MM-DD 정리 | 원본: raw/... | 바뀐 페이지: wiki/...`
- log.md는 지우거나 고치지 않고 덧붙이기만 합니다.

## 하지 않는 것

- raw/ 파일 수정·삭제
- API 키·비밀번호·개인 연락처를 위키에 쓰기
- 위키를 저장소에 올리기(올리기는 위키 동기화 스킬로 사람이 승인한 뒤 함)
