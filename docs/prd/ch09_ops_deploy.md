# 9장: 팀 배포와 업무시간 운영 — 요구사항 정의서 (PRD)

## 1. 개요 및 배경
- **장 목적**: 완성된 팀 대시보드와 에이전트 시스템을 5인 팀이 사내망에서 안정적으로 사용할 수 있도록 systemd 서비스 등록, 업무시간 자동 시작/종료 스케줄링, 백업 및 복구 체계를 구축한다.
- **주요 독자 산출물**: systemd 서비스 유닛, Windows 작업 스케줄러 XML, 자동 백업 스크립트(`scripts/ops/backup.sh`).

## 2. 세부 기능 요구사항
1. **네트워크 및 접근 통제**:
   - WSL2 mirrored 네트워킹 설정으로 사내 LAN IP 바인딩 (`0.0.0.0:8000`).
   - 단일 세션 키 또는 팀 공유 비밀번호 인증 (`HTTP Basic Auth`).
2. **업무시간 스케줄러**:
   - 평일 08:30: Ollama 및 FastAPI 대시보드 자동 기동 (WSL2 부팅).
   - 평일 18:30: 활성 세션 정리, SQLite 데이터베이스 백업 수행 후 안전 종료.
3. **백업 및 장애 복구 (`scripts/ops/backup.sh`)**:
   - 사내 DB(`company.db`)와 사내 위키 디렉터리(`wiki/`)를 일자별 타르볼(`backup_YYYYMMDD.tar.gz`)로 압축 보관.
   - 프로세스 비정상 종료 시 systemd `Restart=on-failure` 복구.

## 3. 교차 검토 (Codex & Claude 협업 노트)
- **Codex**: 24시간 가동 시 발생할 수 있는 메모리 누수와 GPU 스왑 문제를 원천 차단하기 위해 업무시간 기반의 매일 클린 리부트 방식을 제안한다.
- **Claude**: 복잡한 클라우드 쿠버네티스나 도커 스웜 대신 소규모 팀의 단일 GPU PC 환경에 가장 적합한 systemd와 작업 스케줄러를 핵심으로 다룬다.
