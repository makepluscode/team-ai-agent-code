# 1장: 완성 화면과 전체 구조 — 요구사항 정의서 (PRD)

## 1. 개요 및 배경
- **장 목적**: 독자가 최종 완성할 하이브리드 팀 대시보드의 화면과 아키텍처를 첫 장에서 미리 확인하고, 정보의 외부 전송 경계를 이해한다.
- **주요 독자 산출물**: 완성 화면 목업(`prototypes/dashboard_v0.html`), 하이브리드 아키텍처 다이어그램.

## 2. 세부 요구사항
1. **화면 요구사항**:
   - 상단 헤더: 서비스 상태 인디케이터(시스템 정상/온라인), 데이터 경로 범례(`[로컬 LLM]`, `[상용 API]`).
   - KPI 카드 4종: 미처리 문의, 오늘 회의록, 사내 위키 페이지 수, 외부 전송 차단 건수.
   - 메인 그리드 2열:
     - 좌측: 아침 브리핑 패널, 실시간 주의 알림(긴급 견적/서버 용량 경고), 업무 자동화 실행 결과.
     - 우측: 에이전트 대화형 챗봇 패널 (사용자 질의 입력, 실시간 응답, 경로 배지 표시).
2. **아키텍처 요구사항**:
   - 상용 클라우드 API: 범용 질의, 요약, 문장 다듬기.
   - 로컬 LLM (팀 PC): 고객 DB 조회 결과 가명화, 음성 전사 처리, 내부 민감 정보 필터링.
   - 데이터 경계(Boundary): 3등급 데이터(PII, 계약액)는 로컬 경계를 절대 벗어나지 않는다.

## 3. 교차 검토 (Codex & Claude 협업 노트)
- **Codex**: 1장의 완성 화면이 7장에서 재사용 가능한 컴포넌트 단위로 나뉠 수 있도록 CSS 변수 및 시맨틱 HTML 태그를 엄격히 규격화해야 한다.
- **Claude**: 1장 본문에서는 복잡한 기술 설명보다 사용자가 체감할 수 있는 '월요일 아침 출근 시나리오'를 중심으로 서술하고 코드는 제시하지 않는다.
