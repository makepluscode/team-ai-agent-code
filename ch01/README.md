- 준비물: 이 문서와 종이 한 장(또는 메모장)

## 1. 완성 화면 읽기

책의 마지막(11~12장)에 완성하는 대시보드 시제품 화면입니다. 실제 실행 결과가 아니라 설계용 시제품이며, 화면의 건수와 비용은 예시입니다.

- 캠페인 현황: [../captures/ch01_campaign_board.png](../captures/ch01_campaign_board.png)
- 문의 분류와 담당 지정: [../captures/ch08_inquiry_routing.png](../captures/ch08_inquiry_routing.png)
- 견적과 메일 초안: [../captures/ch08_quote_mail.png](../captures/ch08_quote_mail.png)
- 에이전트에게 일 맡기기: [../captures/ch12_agent_chat.png](../captures/ch12_agent_chat.png)

화면을 열고 카드 한 장을 골라 다음 세 가지를 찾습니다.

1. 이 업무는 어느 고객의 어느 캠페인인가
2. 담당 직군(기획·영상·개발·PM)과 지금 상태는 무엇인가
3. 누가 처리했고(로컬 판정·상용 AI·사람), 사람이 확인할 일이 남았는가

세 가지가 모두 보이면 1번을 끝냅니다. 하나라도 찾지 못했다면 원고 1.1절 '[그림 1.1]' 설명을 다시 읽습니다.

## 2. 팀 위키 구조 이해

이 책의 팀 위키는 카파시의 LLM 위키 패턴을 따릅니다(https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f). 2장에서 받을 위키 시작 저장소는 [../ch02/wiki-starter](../ch02/wiki-starter/)에 미리 있습니다. 폴더를 열어 보고 다음 표와 맞춰 봅니다.

| 층 | 위키 시작 저장소의 자리 | 누가 고치나 |
|---|---|---|
| 원본 | `raw/` — 메모·리포트·작업 결과 | 아무도 고치지 않음. 넣기만 함 |
| 위키 페이지 | `wiki/` — 고객·캠페인·리서치·결정 페이지, `index.md`(목록), `log.md`(기록) | 위키 정리 담당 에이전트만 |
| 규칙 파일 | `AGENTS.md` — 페이지를 정리하는 방식 | 위키 담당자 |
| 지침 | `guides/` — 공통 말투(SOUL.md)와 고객별 지침 | 지침 담당자 |
| 스킬 | `skills/` — 팀이 같이 쓰는 작업 절차 | 스킬 담당자 |

[../ch02/wiki-starter/AGENTS.md](../ch02/wiki-starter/AGENTS.md)를 읽고 "원본에 없는 사실은 쓰지 않는다"와 "기존 페이지와 다르면 덮어쓰지 않는다" 두 규칙을 찾습니다. 이 두 규칙이 3장에서 위키를 정리할 때의 완료 기준입니다.

## 3. 역할 나누기

같은 업무 안에서도 맡는 쪽이 다릅니다. 다음 표의 빈칸을 자기 팀 업무 하나로 채워 봅니다.

| 역할 | 맡는 일 | 스튜디오 메리의 예 | 내 팀의 예 |
|---|---|---|---|
| 상용 AI | 조사·요약·초안, 위키 페이지 정리 | 봉봉소프트 제품 소개 초안 | |
| 로컬 판정(Laya, 선택) | 문의 유형·담당 직군·점수 | 받은 메일이 견적 문의인지 판정 | |
| 로컬 전사(Whisper) | 녹음을 글로 | 킥오프 회의 녹음 | |
| 애플리케이션 | 조회·계산·기록 | 단가표로 견적 금액 계산 | |
| 사람 | 금액·발송·발행·위키 변경 승인 | 견적 금액 확정, 메일 발송 | |

로컬 모델은 필수가 아닙니다. 판정을 상용 AI에 맡기는 팀도 책을 끝까지 따라올 수 있습니다(7.4절에서 비교).

## 4. 위키에 넣을 첫 자료 고르기

[worksheet.md](worksheet.md)를 복사해 채웁니다. 여기서 고른 자료는 3장에서 스튜디오 메리 예제를 마친 뒤 자기 팀 위키에 넣는 첫 원본 후보가 됩니다. 실제 고객 정보는 적지 않아도 됩니다. 종류와 이름만 적습니다.
